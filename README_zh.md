# SSPO-Agentic：面向部署时执行挑选的多轮代码 Agent 强化学习

代码 Agent 部署时通常这样用：同一题运行 k 次，用执行检查器过滤，再按输出签名投票，最后提交一个程序。常规强化学习优化的是 pass@1 或 pass@k，不是这个部署指标。SSPO（挑选感知的集合策略优化）直接以 select@k 为训练目标：每次运行拿到的信用，是它对挑选器成功率的精确留一边际贡献，由动态规划在全部 k 元子集上算出。

## 设置

| 项目 | 内容 |
|---|---|
| 模型 | Qwen3-4B（关闭思考），默认上下文 40,960 token，不设生成上限；LoRA r = 64 |
| Agent | 最多 8 轮，每轮一条 bash 命令（编辑 `solution.py`、跑公开样例、提交） |
| 部署系统 | 运行 8 次 → 冻结检查器过滤 → 输出签名多数投票 → 提交一个 |
| 基准 | CodeContests 唯一答案题，按比赛切分；测试集 128 题 / 114 场比赛 |
| 算法 | SSPO（本文）、Dr. GRPO、PKPO pass@8；三者只在优势计算上不同 |

## 结果（种子 0，第 30 步，测试集 128 题，单位 %）

| 策略 | pass@1 | cov@8 | select@8 | 挑选缺口 |
|---|---:|---:|---:|---:|
| 冻结 Qwen3-4B | 42.48 | 64.84 | 58.20 | 6.65 |
| **SSPO** | 49.95 | **69.19** | **64.28** | **4.91** |
| Dr. GRPO | **50.10** | 66.02 | 59.34 | 6.69 |
| PKPO pass@8 | 45.61 | 65.51 | 59.02 | 6.49 |

select@8 配对差（按比赛整簇自助法 95% 区间，Holm 校正）：SSPO − 冻结 +6.08 [+0.65, +11.63]，SSPO − Dr. GRPO +4.94 [+0.26, +9.78]，SSPO − PKPO +5.26 [+0.92, +9.85]，校正后 p = 0.058 / 0.058 / 0.048。目前只有一个训练种子。
